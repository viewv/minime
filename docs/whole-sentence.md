# 整句候选

整句候选（标 `✦`）由一个神经网络整句模型生成：根据拼音和光标前的文字，直接生成整句话，
和引擎的常规候选互为补充。

## 模型

模型来自官方 macOS 安装包，由 `minime-fetch` 下载到 `~/.local/share/minime/official/mac/imeData/`：

| 文件 | 大小 | 内容 |
|---|---|---|
| `decgnr.bin` | 74 MB | 12 层 decoder-only Transformer（GPT-2 结构，隐藏维度 768，词表 10496），权重为 int4/int8 量化 |
| `mpd_e2e.bin` | 3.7 MB | 拼音切分和读音表：把拼音串对应到模型词表，提供每个汉字的读音 |

官方 Windows 版引擎带有这个模型的加载代码，但没有可用的推理实现；MinIME 的推理代码（`src/e2e*.c`）是自己实现的，
只使用官方的模型文件。

## 拼音约束解码

模型本身是一个按字生成的语言模型。如果直接让它自由生成，结果可能漏字、多字或者和拼音对不上。
MinIME 在生成时加上拼音约束：

- 每一步只允许生成读音能接上剩余拼音的字（完整音节，或最后一个还没打完的音节）；
- 拼音用完时只允许结束，没用完时不允许结束；
- 用 beam search（默认 4 条）保留几种候选，选概率最高的作为整句候选。

这样生成的整句一定和输入的拼音一致。同样的方法也用于**简拼**（每个字只打首字母，例如 `zgrm` → 中国人民）
和**模糊音**（打开 z/zh 后，`zong` 也能匹配「中」）。

光标前的文字作为提示输入模型，所以同样的拼音在不同上下文里会给出不同的句子（例如「经理 / 经历」）。

## 和引擎候选怎么配合

1. 每次按键，引擎的候选立即显示，不等整句模型。
2. 同时后台线程用当前的拼音和上下文开始解码；新的按键到来时取消旧的解码。
3. 结果出来后插进候选列表再发一次：概率足够高、或者明显优于引擎首选时放在第一位，否则放在第二位。
4. 以下情况整句候选不放第一位：引擎判断用户打错了字并做了纠正；简拼结果的平均分数太低（通常是错拼硬凑出来的句子）。
5. 选中整句候选时由服务直接上屏。随后服务在一个隐藏的引擎会话里把这句话按词选一遍，让引擎也学到这个句子，
   以后不开整句候选也能直接打出来。

整句候选只用于全拼。输入里出现大写字母（英文）、或者在隐私输入框里时，这次组合不使用整句模型或不学习。

## 计算后端

| 后端 | 要求 | 逐键解码耗时（参考） |
|---|---|---|
| Vulkan | 支持 Vulkan 的 GPU（独显或核显） | 约 12 ms（Radeon 780M 核显） |
| CPU | 支持 AVX2 / FMA / F16C 的 x86-64 CPU | 约 44 ms（8 线程） |

默认先尝试 Vulkan，没有可用的 GPU 时退回 CPU；可以用环境变量 `MINIME_E2E_BACKEND=cpu|vulkan` 指定。
按键之间复用上一次计算的缓存，只计算新增的部分。

## 开关

- 「MinIME 设置 → 输入 → 整句候选」或配置项 `WholeSentence`。
- 没有下载整句模型时，这个功能自动不启用，其余功能不受影响。
