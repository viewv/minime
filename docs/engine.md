# 引擎的原生装载

微信输入法的核心是一个跨平台的 C++ 引擎。Windows 版把它编成 `libwxhld.dll`（x86-64），
官方的 Windows 服务进程通过一组 C 接口（`wxime_*`）调用它。MinIME 直接在 Linux 进程里运行这个 DLL。

## 为什么不需要 Wine，也不需要指令转译

引擎和 Linux 都运行在 x86-64 上，机器码本身不需要翻译。真正需要解决的只有两件事：

1. **装载**：把 PE 格式的 DLL 映射进内存，完成重定位和导入绑定，初始化线程局部存储（TLS）并调用入口函数；
2. **系统调用**：引擎调用的 Windows API（内存、文件、线程、同步、时间等）要有对应的实现。

MinIME 为此实现了一个 PE 装载器和一层精简的 Win32 兼容层（`loader/`），只覆盖引擎实际用到的那部分 API。
引擎的机器码原样执行，和在 Windows 上运行的是同一份代码。

## 装载器做了什么

- **映射和重定位**：按节映射 DLL，处理 64 位重定位，设置各节的内存保护。
- **映像缓存**：DLL 文件里的节按 512 字节对齐，不能直接按页映射。第一次装载时，装载器把重定位好的映像
  按内存布局存到 `~/.cache/minime/pe/`，以后直接映射这个文件：没执行到的代码不读进内存，
  内存紧张时系统可以丢掉这些页、需要时再从文件读回，不占交换分区。映像内容和装载地址都和之前一样，
  对引擎是透明的。原 DLL 一变（大小、修改时间等）就重新生成；删掉缓存目录也没关系。
  `MINIME_PE_CACHE=0` 可以关掉，退回整段复制进内存。
- **导入绑定**：引擎依赖的同目录 DLL（XNet、TensorFlow Lite 等）递归装载；系统 DLL（KERNEL32 等）的导入
  绑定到兼容层的实现。网络组件 `ime_net.dll` 不装载，它的导入换成 MinIME 自己的网络兼容层，
  请求经 Unix socket 交给 netd（见 [cross-device](cross-device.md)）。
- **调用约定**：Windows x64 和 Linux（System V）的调用约定不同，兼容层的函数都用 Windows 调用约定编译。
- **线程环境**：Windows 代码通过 `gs` 段寄存器访问线程信息块（TEB）和 TLS。装载器为每个调用引擎的线程
  建立 TEB，并为引擎自己创建的线程做同样的准备。
- **初始化**：执行 TLS 回调和各 DLL 的入口函数。

用户数据目录、词库目录这些路径由 engined 在初始化引擎时传入，引擎的文件操作经兼容层落到 Linux 文件系统上。

## 缺少整句组件时的处理

Windows 安装包不带引擎内置的整句组件，而引擎默认会尝试使用它。MinIME 在创建会话前让引擎跳过这个组件，
和官方 Windows 客户端的行为一致。这一处理只在内存中进行，磁盘上的官方文件保持下载时的原样。
（MinIME 的整句候选用的是自己的推理实现，见 [whole-sentence](whole-sentence.md)。）

## 性能

在同一台机器（AMD Ryzen 笔记本）上，与用 Wine 运行官方引擎对比：

| 指标 | MinIME | Wine |
|---|---|---|
| 一次按键的往返（平均） | 约 3.3 ms | 约 5.2 ms |
| 引擎服务内存 | 约 245 MB | 约 330 MB（含 wineserver 和桥接进程） |
| 启动（装载、初始化、加载词库） | 150–180 ms | 约 250 ms（wineserver 已在运行时） |

引擎本身的计算量不变；省下来的主要是 Wine 的系统调用转换和 wineserver 往返、额外的桥接进程，
以及堆分配：MinIME 使用原生分配器 jemalloc，比 Windows 堆的实现更快。

内存的大头是词库、模型和引擎自己的堆。0.1.2 起，装载器按文件映射 DLL（见上面的「映像缓存」），整句模型的权重
上传到显存后也不再在内存里保留一份。打完 45 段基准输入后（整句模型开，Vulkan）：

| | 之前 | 现在 |
|---|---|---|
| 常驻内存（RSS） | 377 MB | 282 MB |
| 其中匿名内存（只能换到交换分区） | 143 MB | 100 MB |
| DLL 映像 | 32 MB（匿名） | 19 MB（按文件映射，只有执行到的部分） |
| 整句模型文件映射 | 70 MB | 0 |

常驻内存里剩下的文件映射（词库等，约 180 MB）系统可以随时回收，真正需要常驻的是约 100 MB 匿名内存，
主要是引擎加载的词库索引和语言模型。

## 限制

- **只支持 x86-64**。装载器不做指令转译，引擎是 x86-64 机器码。
- **C++ 异常**：引擎内部抛出 C++ 异常时需要 Windows 的结构化异常展开，兼容层还没有实现。
  遇到这种情况引擎服务会退出，由 systemd 在一秒内重启，正在输入的内容会丢失。日常使用中很少遇到。
- **引擎版本**：目前固定使用 Windows 版 3.0.1.35。更换版本需要重新验证引擎接口和会话配置。
